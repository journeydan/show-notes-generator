Fix the slug divergence bug between client and server.

## Problem
When the API is available, `saveEpisode` in src/storage.js saves to localStorage (using its own slug from nextEpisodeNumber()) AND sends a POST to the API. The server computes a DIFFERENT slug from the episode number. This creates two separate files for the same episode — one in localStorage and one on the filesystem.

## Fix 1: server.js
In the POST /api/episodes handler, accept an optional `slug` field from the request body. If provided, use it directly instead of computing one from the episode number.

Change `buildEpisodeMarkdown` to also accept an optional `slug` parameter. If slug is provided, skip the slug computation. If not, compute from number as before.

In the POST handler, read `slug` from req.body and pass it to buildEpisodeMarkdown.

The slug computation only happens in one place (episodeSlug function) and stays as fallback.

## Fix 2: src/storage.js
In the `saveEpisode` function, when calling tryAPI to POST to the server, pass `slug` in the body if the localStorage already has a slug for this episode. The localStorage fallback uses `nextEpisodeNumber()` or the existing slug — pass that same slug to the API so both sides agree.

The pattern: compute the slug FIRST (same logic as before), then pass it to both the API call AND the localStorage save.

## Verify
After both changes, run npm run build.
